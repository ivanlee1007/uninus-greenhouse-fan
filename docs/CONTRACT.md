# Greenhouse fan 0.5.3 implementation contract

The v8 design reference stays global-policy-above-grid with responsive columns. No demo width control is shipped.

- One integration config entry owns one group: shared policy/duration/policy_revision, complete device inventory/bindings/manual holds/global mode in one verified HA Store registry. Entry data/options supply migration input only; stale options cannot resurrect a policy. Native Shared policy reads/saves that authority before OptionsFlowManager updates unrelated entry metadata.
- Approved A threshold editor exists only inside the expanded global strip: two wide group boxes, stacked narrow, Start above Stop. Range input creates a draft only; Cancel discards/reloads, admin Save sends all four finite thresholds plus the original policy revision, without duration. Polls cannot silently rebase drafts; unrelated registry changes do not change policy revision. Pending writes serialize other card actions; failures/conflicts preserve drafts/effective policy/timers. Changed successful saves reset duration state but preserve holds/global mode and call no services. Focused/dragged slider DOM survives live polls; stale scope/detach results are ignored.
- Default slider range is temperature 0–50, humidity 0–100, step 0.1; valid legacy temperature endpoints expand the range visibly, never clamp. Backend accepts temperature −20–80, humidity 0–100, Stop ≤ Start; strict boolean/string/nonfinite rejection applies to native and WS inputs. CI requires native policy/storage tests and real browser approved-A geometry/interaction gates.
- Native Options menu: named list, Add, Edit, Remove with confirmation, shared policy. Device form saves name/output/optional complete source pair atomically. Cancel is read-only. Stable opaque IDs are independent of name/output.
- Native output EntitySelector permits fan/switch; source selectors permit sensor temperature/humidity classes. Sources must use °C/%; incomplete pairs fail. Clearing both produces a manual-only device.
- Device records migrate from legacy binding/hold union with deterministic stable IDs, no actuation and idempotent reload. Existing YAML literal fan_entity resolves only configured ownership; legacy unstored display-only outputs need explicit Add.
- Duplicate output ownership within/across loaded groups is rejected. An unloaded other group conservatively blocks assignment and control until every group loads. No arbitrary-output control endpoint.
- Editor only picks selected-group inventory including offline records, display names/order/group/appearance. Dashboard Save remains display-only. No bind call, backend sensor-source inputs, Apply/Discard, revision or ID user field. Display-only subtitle supports text or one unrestricted native entity picker plus optional attribute and state unit; clears hide and legacy text stays until supplied. The authoritative value-changed event immediately emits config, never writes backend, and active search is not remounted by live refresh.
- New selections store device_id and follow output edits; deleted IDs never fall back. Literal fan_entity remains backward compatible.
- Snapshot devices fields are allowlisted device_id/name/fan_entity/temperature_entity/humidity_entity. Runtime is output-keyed; /get and /groups are authenticated read-only.
- Admin-only /set_control_mode accepts entry_id + control_mode auto/manual for an actual loaded group. One verified registry transaction retains inventory and publishes the durable group gate; Manual holds physical output without services, Auto clears every individual hold without immediate actuation. All configured/hidden/offline/unknown devices are included. Mode changes serialize against CRUD/manual/evaluation; pre/post persistence active checks prevent disposed publication. Manual rejects individual Resume in backend and renders no Resume button. Individual holds under global Auto alone show Resume; pending mode writes retain authoritative visibility. The global strip pins the borderless, transparent switch to its right edge, with exactly 自動 before the track and wrapped threshold pairs on the left. Reload/add/edit preserve the global gate.
- Auto-only per-reading warning color uses finite native values and strict > on-threshold, not rounded display or output feedback. No warning rows; underlined high-contrast colors retain clear light/dark semantics. Compact geometry gates retain fixed 2 columns and 44px touch targets.
- Admin-only /manual accepts configured owned fan_entity and on/off/auto. Holds save before dispatch; no sensors needed for manual. Resume only clears hold. Auto remains fail-closed with duration/hysteresis.
- Compatibility /bind can update an existing configured output only, using an internal optimistic revision. It cannot add unconfigured bindings and is never called by the editor.
- Sources reset pending timers preserving manual holds; name-only edits leave them unchanged. Output replacement keeps identity but clears old holds/timers and does not actuate old/new hardware while saving. New output auto starts from fresh evaluation (zero duration may act next tick). Removal clears automation/holds without switching physical state.
- HA Store uses atomic_writes=True. Before candidate writes, an atomically persisted and read-verified .pending journal retains the previous HA JSON envelope. Candidate bytes receive up to three readback attempts. Failed verification triggers verified rollback; only a reconciled prior record is a retry-safe save failure. Failed rollback/verification disables the group and retains durable quarantine, blocking setup before Store loads after restart. Cancellation drains the real executor writer, then rolls back while locks remain held; unload/shutdown never dispatch after awaited persistence. See [persistence recovery](PERSISTENCE.md). Native Options errors retain input; stale revision requires reopening.
- Display-only `show_device_details` is normalized to a typed boolean (only literal false hides; legacy/default/stub true). One editor checkbox labelled 顯示控制模式與診斷訊息 affects all displayed fans and emits config immediately. False omits the entire `.device-details` including control-mode/pending-report line and reason paragraph, not headers/badges/readings/buttons/global controls/outer note. Save/reopen and hass refresh preserve it, with no backend writes and no reserved blank height.
- Healthy background reads do not set control-loading/disabled gates. Five-second polls coalesce while a read is pending, while explicit newer reads and commands invalidate old completions. Keyed live DOM patches retain unchanged fan articles/rotors/manual controls and global controls; threshold sliders/Save/Cancel never detach on a healthy refresh. Only changed attributes/text are written; no redundant disabled mutations. Actual pending commands, initial loading, error reads and unavailable scopes remain disabled/guarded. Existing epoch/config identity and original dirty policy revision rules remain authoritative; disconnect cancels polling and invalidates pending work.
- Browser release gates require three controlled five-second polls plus frequent hass updates, zero stable-control removals/disabled-attribute changes and retained focus/animation/scroll/open state, along with real changed-state DOM updates, deferred read/action races and fail-closed errors/unload/scope. Checkbox Save/reopen is exercised by an offline Dashboard Save host, not live HA storage UI. Full native backend and existing pointer/keyboard/manual gates remain mandatory.
- Display-only `lock_readings_right` accepts only literal true; legacy/default/stub false. The global native checkbox 溫濕度固定在風扇右側 emits typed config and survives Dashboard Save/reopen without backend writes. Opt-in scoped CSS keeps readings right of the complete scaled animation in auto/1/2 at tested card widths 320/390/500/630/720/1080px, both themes, details on/off; fixed-two stays two and no horizontal overflow is hidden. 320px is the supported tested minimum; arbitrary smaller widths/unbounded numeric lengths are not promised. Default CSS remains unchanged. Healthy enabled-mode refresh preserves nodes, focus and animation identity; readings update and existing error/pending/scope guards remain authoritative. The seventh browser gate records geometry and height reductions at 390/500px fixed-two, plus editor round trip and three-poll/18-hass no-flash evidence.
- Repository-only authorization: no commit/push/release/deploy/restart/live HA/hardware operation.
