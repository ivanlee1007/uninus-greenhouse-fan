# C 方案 v8：自動欄數與逐顯示項目感測來源

範圍：離線可操作設計 Demo；**沒有**修改 Home Assistant、既有自動化或實體風扇。正式方案尚未實作。

## 顯示
- 全域門檻區永遠在風扇設備格上方；收折時只露出溫度與濕度上下限。
- 「每列設備數：自動排列」依**卡片內風扇格的可用寬度**，使用 CSS Grid `repeat(auto-fit,minmax(min(100%,310px),1fr))`。四個項目隨寬度由 1 → 2 → 3 → 4 台／列。三欄時是 3+1，**不**為維持 2×2 而特判台數。固定一欄、二欄是獨立選項。
- 本文預覽外的滑桿只模擬 Dashboard 容器寬度；不是正式卡片的寬度設定。過寬時縮放預覽，可切「原寸捲動」。

## 設定邊界
- 卡片設定每筆顯示項目：風扇 Entity、顯示名稱、溫度 Entity、濕度 Entity；可移動、新增、移除。移除顯示項目不刪除既有後端設備綁定。
- Integration 設定：共用啟動／停止溫濕度門檻及持續秒數；**不提供另一套逐台溫濕度來源設定表單**。
- Demo「儲存卡片設定」在本地同時更新顯示來源與控制器綁定。草稿期間不改控制器；儲存後重設受影響設備的條件計時。驗證涵蓋指定高溫感測器後，風扇 3 等待 120 秒並自動開啟。

## 正式實作必須另行落地的契約
- Home Assistant 的 Lovelace 卡片 YAML 與 Integration 設定是不同儲存層，**單靠卡片 `config-changed` 或按「儲存卡片」不會自動修改後端**。離線 Demo 的同步不可當作 HA 已有的功能。
- 建議由 Integration 維持唯一的 `(group_id, fan_entity_id) → (temperature_entity_id, humidity_entity_id)` 綁定登錄；卡片編輯器提供上述四欄，透過有權限驗證及版本檢查的 Integration API 寫入綁定。卡片正式畫面也讀同一登錄；卡片 YAML 只存群組／設備引用及顯示名稱，不另存會漂移的感測來源。Integration Options 頁只管共用門檻／持續秒數，不重複顯示逐台來源表單。
- 多張卡片引用同一群組／風扇時同時看同一份綁定；並行編輯採修訂版本檢查，衝突須保留草稿、告知使用者刷新；權限不足或寫入失敗時不得假裝卡片／後端已同步。正式卡片編輯器需要清楚的「套用感測來源」提交及結果狀態，避免把 Lovelace 的 Save 誤當成後端已更新。
- 對於未在任何卡片設定來源的風扇，後端不得默默選錯感測器；提供「未綁定」狀態並停止該設備的自動判斷。移除卡片顯示項目不應清除已有後端綁定，除非使用者另外確認解除綁定。
